Two verification levels

Field-verified records have individually checked core metadata. Source-linked records were indexed from official developer model listings but still contain fields awaiting individual verification.

Model Detail 2.0

Every record exposes eight consistent sections: Weights, License, Hardware, Formats, Lineage, Training assets, Sources and Verification history.

Hardware estimates

When a total parameter count is available, weight-only memory is estimated as roughly 2 bytes per parameter for BF16/FP16, 1 byte for FP8/INT8 and 0.5 byte for INT4. These are not end-to-end VRAM requirements: runtime overhead, KV cache, activations and sharding can materially change deployment needs.

License handling

We do not infer commercial permission from the phrase “open weights.” If a license has not been checked individually, the record says so and links to the primary source.

Source hierarchy

Official developer repositories and organization listings are primary sources for repository existence. Model cards, license files and official documentation are used for field-level verification.

Corrections

The registry lives in public version control. Corrections can be proposed through GitHub and remain attributable in history.
